## 6. D6 — Immediate Next Task (exact plan)

**Goal**: link each recorded workflow instance to the behavior signatures that realized
it, WITHOUT inventing semantics and WITHOUT changing identity/migration. The linkage is
pure observation-derived: same app, same session, temporal co-occurrence.

### Root cause to solve
`RecordedWorkflow.instances` holds workflow IDs, but nothing connects a workflow instance
to the signatures (`behaviorSignatures` store) whose anchors/edges occurred during that
workflow's time span in that session. CP8's `workflowPatternIds` on signatures is `[]`
and `workflowPatternAbsence: 'linkage-pending'` (contract-queries.ts:203–204) — an
honest typed-absence marker awaiting D6.

### Files to change (minimal)
1. **`src/understanding/enrichment/semantic-types.ts`** — extend `RecordedWorkflow`:
   ```ts
   /** Signature ids co-occurring in the same session within the workflow's span. */
   signatureIds: string[];
   /** Typed absence marker until linkage is built. */
   linkageState: 'linked' | 'linkage-pending';
   ```
   (Keep all existing fields; additive only.)
2. **`src/understanding/persistence/knowledge-repository.ts`** — upsert merge for the new
   fields (union of signatureIds, linkageState from both sides, dedup); extend
   `findLegacyPatternRow` to also migrate rows lacking the new fields.

   aggregated** (`aggregateRecordedWorkflows` in `recorded-workflow.ts`): compute linkage
   from prior + current instances using session-local signature spans (see acceptance).

   (~line 431–449) via `knowledge-persistence-service.persistRecordedWorkflows`; an export
