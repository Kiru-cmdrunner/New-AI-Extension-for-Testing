# C5.2 Custom Dropdown Runtime Defect — Postmortem

**Date**: 2026-07-16
**Milestone**: C5.2 Dropdown & Select Recording Foundation
**Severity**: Critical — dropdown interactions completely lost on real-world apps
**Status**: Fixed

## Summary

The select-content-script only listened for native DOM `change` events to detect
dropdown selections. Custom dropdown components (OrangeHRM OXD Vue3, Adani One
React) never dispatch `change` events — they use JavaScript-based selection via
`@mousedown`/`@click` on `[role="option"]` elements and framework reactivity.

The `change` event listener never fired → `handleChange()` never invoked →
`SELECT_CAPTURED` never sent → background SW never received → no interaction
in any artifact pipeline.

## Root Cause

`select-content-script.ts` had a single detection mechanism:
```js
document.addEventListener('change', handleChange, true);
```

This only works for native `<select>` elements. All modern web applications use
custom dropdown components that do NOT dispatch native `change` events.

## Evidence from OrangeHRM OXD Source Code

OXD (Orange eXperience Design — Vue3 component library for OrangeHRM 5.x):

1. **SelectText.vue** (trigger): `<div class="oxd-select-text-input" tabindex="0">`
   - NO `role="combobox"`, NO `role="listbox"` — just plain divs with classes
   - `@mousedown.prevent="onToggle"` opens/closes the dropdown

2. **SelectDropdown.vue**: `<div role="listbox" class="oxd-select-dropdown">`
   - Only rendered when `dropdownOpen` is true (`v-if="dropdownOpen"`)

3. **SelectOption.vue**: `<div role="option" class="oxd-select-option" @mousedown="onClick">`
   - `onClick()` emits Vue event `this.$emit('select')` → `update:modelValue`
   - **NO native `change` event is dispatched**

4. **SelectInput.vue**: receives `$emit('select')` → `onSelect(option)` → `$emit('update:modelValue', option)`
   - Pure Vue reactivity — no DOM event

## Fix Applied

Added a second detection mechanism to `select-content-script.ts`:

1. **`OPTION_SELECTOR = '[role="option"]'`** — detects custom dropdown options
2. **`handleOptionClick(event)`** — mousedown-based handler for `[role="option"]` clicks:
   - Gate 1: `isTrusted` check
   - Resolves parent dropdown container via `closest('[role="listbox"], [role="combobox"]')`
   - Gate 2: ownership check
   - Gate 5: enabled/interactive check
   - Gate 4: value change via pre-state map comparison
   - Extracts selected value from `textContent`
   - Commits `SELECT_CAPTURED` and claims ownership
3. **`document.addEventListener('mousedown', handleOptionClick, true)`** — capture phase

Also updated `click-content-script.ts`:
- Added `DROPDOWN_OPTION_SELECTOR = '[role="option"]'`
- Added **Decision 2d**: skip `[role="option"]` clicks in generic click handler
- Prevents duplicate Click+Select for the same interaction

## Key Learning

Custom dropdown components that follow WAI-ARIA patterns use `role="option"`
elements with JavaScript click handlers. They do NOT dispatch native `change`
events. A recorder must have TWO detection paths:
1. `change` event for native `<select>`
2. `mousedown`/`click` on `[role="option"]` for custom dropdowns

This applies to ALL custom dropdown frameworks: React Select, MUI, Ant Design,
Headless UI, Radix UI, OXD, vue-select, and similar.

## No Frozen Rules Modified

- C5.1 product strategy: unchanged (one interaction type, value-based model)
- C5.1 5-gate decision tree: same gates applied in same order
- C5.1 ownership priority: select > click maintained via Decision 2d
- C5.2 recording architecture: same registration mechanism, same message types
