# C3.3 Pre-Hover Baseline Strategy — Design Review

## Date: 2026-07-15
## Status: Design review complete. Recommendation: DOM Clone Baseline.

## Problem
CSS :hover is applied by the browser during hit-testing, which completes BEFORE
any mouse event (mouseenter, mouseover, mousemove) is dispatched. Therefore, no
event-based approach can capture the pre-hover state. The current C3.3 implementation
takes its baseline at mouseenter — but by that time the submenu is already display:block.

## Verified with Live Chrome Evidence
- At mouseenter (capture phase): submenu display = block (already visible)
- At mouseover: submenu display = block (already visible)
- At mousemove on target: submenu display = block (already visible)
- After mouse leaves: submenu display = none
- Clone approach while hovering: clone submenu display = none (CORRECT pre-hover state)

## Candidate Approaches Evaluated (8 total)

### 1. mouseenter Baseline (Current — DEFECTIVE)
Baseline taken at mouseenter event. :hover already applied. Cannot detect transitions.

### 2. mouseover Baseline
Same timing issue — :hover applied before mouseover fires.

### 3. mousemove Pre-arrival Detection
Listen for mousemove approaching the target, capture baseline before arrival.
Rejected: non-deterministic, depends on mouse velocity/trajectory, misses fast moves,
very complex, high false negative rate.

### 4. Periodic Background Snapshots
Take snapshots of the entire nav periodically, keep last-known pre-hover state.
Rejected: continuous performance cost, memory growth, non-deterministic timing,
snapshot may be stale or miss rapidly toggled menus.

### 5. CSS Rule Static Analysis
Read stylesheet rules, find :hover rules, determine what the non-hovered display
would be without actually computing it.
Rejected: can't resolve cascade (multiple rules, specificity, !important), can't
read cross-origin stylesheets (SecurityError on sheet.cssRules), extremely complex.

### 6. DOM Clone Baseline (RECOMMENDED)
Clone the hover target's parentElement subtree, append to a hidden off-screen
container, read getComputedStyle on all descendants. The clone is NOT hovered
(clone is in off-screen container, not under the cursor), so :hover rules don't
apply. This produces the exact pre-hover computed style.

Performance: avg 0.05-1.5ms per clone depending on subtree size. Max ~8ms for
500 elements. Runs once per hover candidate (not continuous).

Verified:
- Correctly shows display:none for CSS :hover menus
- Correctly shows visibility:hidden for fade patterns
- Correctly shows opacity:0 for opacity transitions
- Works with CSS-in-JS (styled-components) injected styles
- Works with sibling selectors (~), child selectors (>), descendant selectors
- Works while the page is actively being hovered
- Match between clone and non-hovering computed style: EXACT

### 7. Stylesheet Toggle
Temporarily disable :hover rules, read computed style, re-enable.
Rejected: forces full layout recalculation, causes visual flicker, race conditions
with other scripts, destructive to page state.

### 8. Overlay Inspection (elementFromPoint probe)
Temporarily hide the element, use elementFromPoint to check what's behind it.
Rejected: doesn't help with :hover detection, destructive to page rendering.

## Recommendation: DOM Clone Baseline

### Why it's better than current mouseenter baseline:
- Correctly captures pre-hover state (:hover doesn't apply to off-screen clone)
- Deterministic: same DOM + CSS = same result every time
- Framework-agnostic: operates on DOM API, no framework knowledge needed
- Performant: <2ms avg for typical nav, runs once per candidate
- Preserves existing Gate 5 architecture: still produces a VisibilitySnapshot,
  still compared by detectVisibilityTransition(), still consumed via
  candidate.qualified

### What changes (implementation only):
- In handleMouseEnter: replace takeVisibilitySnapshot(visibilityRoot)
  with a clone-based snapshot function
- The clone-based snapshot produces the same VisibilitySnapshot type
- detectVisibilityTransition, createVisibilityTransitionDetector, Gate 5 logic:
  all unchanged
- candidate.qualified consumption: unchanged

### What does NOT change:
- C3.1 frozen product rules
- 6-Gate Hover decision process
- Interaction pipeline (HOVER_CAPTURED message, service worker, timeline)
- Artifact generation pipeline (canonical steps, execution JSON, Playwright)
- MutationObserver (Mechanism 1) — still runs in parallel

### Limitations:
- Elements with inline style display:block won't be hidden in clone (but these
  are visible in the real DOM too, so no false transition)
- JS event handlers don't fire on clone (clone is detached from event listeners)
  — but this is fine, we're checking CSS state, not JS behavior
- pointer-events:none elements: clone approach handles these correctly (pointer-events
  doesn't affect getComputedStyle display resolution)
