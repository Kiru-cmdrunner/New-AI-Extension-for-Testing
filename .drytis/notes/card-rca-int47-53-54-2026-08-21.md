## Why classification failed (all three)

`isInteractiveElement` (`patterns.ts:198-209`): plain DIV/SPAN, no role, no tabIndex,
classes match INTERACTIVE_CLASS_RE tokens for none. Dropdown `detectTrigger`
(`dropdown.ts:46-70`) requires trigger shape — an option-ish click with no armed
trigger is ignored (pendingOptionClick parking unreachable pre-lifecycle). RadioButton
(`radio-button.ts:34-51`) needs radio shape. Click fallback (`click.ts:32-54`) needs
isInteractiveElement OR `isInsideOpenSelectionSurface` (`patterns.ts:181-187`) — both
failed. = RCA cluster C3 (definition vocabulary).

## NEW BUG FOUND — LP1 role branch is dead code

`getAncestorRoles` formats entries as `div[role=dialog]` (`dom-context-extractor.ts:100-107`)
but `OPEN_SELECTION_SURFACE_ROLES.has(role)` (`patterns.ts:181-187`) tests bare
tokens ('dialog', 'listbox', …) → role branch can NEVER match. Only the class branch
of LP1 is live. Additionally DIALOG_RE (`component-detector.ts:57`) ⊄
OPEN_SELECTION_SURFACE_CLASS_RE: `popup` enriches as Dialog but does NOT qualify a
Click. int-47's click was inside a real dialog (Dialog tag proves ancestry) yet LP1
couldn't recognize it — most plausibly role=dialog ancestor (dead branch) or a
`popup`-class ancestor (missing vocabulary). Fix candidates for Phase 6D: normalize
role format in the LP1 check; align DIALOG_RE ⊆ surface RE.
