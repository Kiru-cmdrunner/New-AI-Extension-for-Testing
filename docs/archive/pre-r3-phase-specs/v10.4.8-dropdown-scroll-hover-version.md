# Spec: Dropdown Grouping, Tiny Scroll, Post-Click Hover, Version Fix

## Problems (4 bugs from user feedback)

### Bug 1: Dropdown SELECT not grouped — shows as CLK, INP, CHG separately
When user clicks a `<select>` dropdown, browses options (takes seconds), then selects a value, the classifier splits the events into separate interactions because the 500ms grouping window is too short for real-world dropdown usage. A dropdown interaction should be grouped across the full click→change span regardless of time.

**Events observed**: `click@21:31:22` → `input@21:31:25` → `change@21:31:25` (3 second gap)
**Expected**: One `NativeDropdown` interaction
**Actual**: `CLK` + `INP+CHG` → two separate interactions

### Bug 2: Tiny scrolls still recorded
The scroll baseline only updates when a scroll passes the 100px threshold. Multiple small scrolls accumulate and eventually cross 100px as a sum, even though no individual scroll was deliberate.

**Events observed**: Multiple `SCROLL` events on `HTML` element.

### Bug 3: MOUSEENTER after date selection
After clicking a date in a calendar, the calendar closes and the mouse pointer is now over a different element. A new `mouseover` event starts fresh hover tracking. The calendar-closing DOM mutation (detected by MutationObserver) triggers `hoverMutationSeen=true` → fires a spurious `mouseenter` within 300ms.

**Event observed**: `evt-0027 MOUSEENTER "Save up to ₹5,000..."` at same timestamp as date click.

### Bug 4: Extension version shows v10.4.6
The version string is **hardcoded in `src/sidepanel/index.html`** at `v10.4.6`. Updating `manifest.json` to 10.4.7 did not update the UI-displayed version. Need to read the version dynamically or keep both in sync.

## Solution

### Fix 1: SELECT Element Grouping (interaction-detector.ts)
Extend the grouping window for events on the **same element** when the element is a SELECT (tag=SELECT or ariaRole=listbox). Instead of the standard 500ms window, use a **5-second window** for SELECT elements. This covers the real-world time a user spends browsing dropdown options.

### Fix 2: Always Update Scroll Baseline (deterministic-recorder.ts)
Update `lastScrollTop`/`lastScrollLeft` on **every scroll event** (before the threshold check), so small scrolls don't accumulate. Only fire the recorded event when a *single* scroll exceeds the threshold.

### Fix 3: Post-Click Hover Cooldown (deterministic-recorder.ts)
After any click, set a timestamp (`lastClickHoverSuppressUntil`). In the `mouseover` handler, if `Date.now() < lastClickHoverSuppressUntil`, skip hover tracking entirely. Use a **1.5-second cooldown** — long enough to cover calendar close animation + DOM mutation settling, short enough to not miss legitimate hovers after the user pauses.

### Fix 4: Version Display (sidepanel/index.html)
Update the hardcoded version string to `v10.4.7`.

## Acceptance Criteria

- [ ] SELECT click + input + change within 5 seconds on same element = one `NativeDropdown` interaction
- [ ] Multiple small scrolls (<100px each) do NOT produce scroll events
- [ ] No MOUSEENTER fires within 1.5s after a click (cooldown suppresses new hover tracking)
- [ ] Extension version shows `v10.4.7` in the sidepanel footer
- [ ] Regular text input click + type + blur still groups correctly
- [ ] Regular hover with real CSS reveal still works (after cooldown)
- [ ] All existing tests pass
