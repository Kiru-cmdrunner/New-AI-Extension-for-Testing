# Spec: Suppress Redundant Raw Events (Checkbox + Dropdown)

## Problems

### Bug 1: Checkbox click produces 4 raw events (CLK label + CLK checkbox + INP + CHG)
When clicking a checkbox wrapped in a `<label>` (common in forms), the browser fires:
1. `click` on the `<label>` element
2. `click` on the `<input type="checkbox">` 
3. `input` event on the checkbox
4. `change` event on the checkbox

All four are captured by the recorder, creating noise. The `input` and `change` events are redundant — the click handler already captures the checked state via deferred read. The label click is a duplicate of the checkbox click (labels forward clicks to their associated input).

### Bug 2: Dropdown SELECT selection shows CLK + INP + CHG
When selecting a value from a `<select>` dropdown, the browser fires:
1. `click` on the select element
2. `input` event on the select
3. `change` event on the select

The `input` event on SELECT elements is redundant with `change` — it fires at the same time with the same value. Only `change` carries the committed value.

## Solution

### Fix 1: Suppress input/change on checkbox/radio elements (deterministic-recorder.ts)
In the `input` and `change` event handlers, skip processing when the target is a checkbox or radio input. The click handler already captures the full state transition (checkedBefore → checkedAfter via deferred read). This eliminates the INP and CHG noise.

### Fix 2: Suppress input on SELECT elements (deterministic-recorder.ts)
In the `input` event handler, skip processing when the target is a SELECT element. The `change` event carries the committed value; `input` on SELECT is redundant.

### Fix 3: Suppress click on label elements wrapping inputs (deterministic-recorder.ts)
In the click handler, when the click target is a `<label>` element, check if it wraps (or is associated via `for`) an input element. If so, skip the click — the input's own click event captures the interaction. This prevents duplicate CLK events.

## Acceptance Criteria

- [ ] Clicking a checkbox wrapped in a label produces ONE click event (on the input), not 4 events
- [ ] Clicking a checkbox NOT in a label produces ONE click event, not 3 (no INP/CHG)
- [ ] Selecting a dropdown value produces click + change (no INP)
- [ ] Regular text input still produces focus + input + blur normally
- [ ] Regular button click still works normally
- [ ] All existing tests pass
